# 共用地圖圖資維護

維護者在 GitHub 更新此資料夾並重新部署網站後，所有使用者會讀取該次部署的相同圖資。網站不會即時讀取 GitHub main 分支，也沒有訪客上傳功能。請勿提交機密、個資或無權公開的圖資；這些檔案可由網站訪客下載。

## 上傳 SHP

1. 將同一份圖資、同名的 `.shp`、`.shx`、`.dbf`、`.prj` 放在 ZIP 根目錄，建議也包含 `.cpg`（例如 UTF-8）以利辨識中文欄位。不要使用 RAR 或 7z。
2. `.prj` 必須正確描述原始座標系統，尤其是 TWD97 / TM2 公尺座標。系統使用 shpjs 轉換為 WGS84；若該投影不受支援，請用 QGIS 匯出成 EPSG:4326 的 GeoJSON。不要只改副檔名或把公尺座標當成經緯度。
3. 將 ZIP 上傳至 `public/maps/`，例如 `ecological-areas.zip`。檔案名稱不要含路徑、`..`、`?` 或 `#`。
4. 編輯同資料夾的 `layers.md`：

```markdown
# 共用圖層

## 生態敏感區

- 檔案：ecological-areas.zip
- 顏色：#588157
```

每個 `##` 標題代表一個圖層，標題文字就是顯示名稱。新增圖層只要複製這個區塊。`檔案` 只填檔名（不加 `public/maps/`），不可重複；`顏色` 為六碼十六進位色碼，省略時使用 `#588157`。也支援 `.geojson` / `.json`，內容須為 WGS84 經緯度的 GeoJSON FeatureCollection。

5. 執行 `npm ci`（首次安裝或套件變更時）、`npm run lint`、`npm run build`、`npm run dev`。在數位地圖頁確認圖層範圍、屬性中文、圖層開關及座標搜尋。可拖曳、縮放地圖查看圖資，不會自動移走預設座標中心。
6. 將圖資與清單一起提交 GitHub，經審核後使用團隊既有網站部署流程發布。使用者重新載入頁面後取得該次部署版本。只有提交 GitHub 而未重新部署，不會更新已發布網站。

刪除所有圖層區塊即可停用全部共用圖資。更新前請保留舊版本，錯誤時可回復該次提交並重新部署。

## 顯示與容量

- 使用 Leaflet 顯示圖資，OpenStreetMap 提供底圖（需可連線至 `tile.openstreetmap.org`）。底圖連線失敗時，仍可定位及查看本機共用圖層，但背景會空白。正式大量流量請依 OpenStreetMap 使用政策選擇適合的圖磚供應商。
- ZIP 在瀏覽器中解壓及解析，圖資越大載入越久。建議單檔先控制在 10 MB 以內，較大資料先以 QGIS 簡化幾何或分層；GitHub 一般 Git 檔案限制亦適用。請勿使用只含 LFS pointer、未在部署前取得實體內容的檔案。
- `.prj` 缺漏可能造成位置錯誤，請務必提供並與已知地點比對。GeoJSON 一律使用 `[經度, 緯度]`，非 `[緯度, 經度]`。
- 空圖層不會顯示任何圖徵；下載、解析或座標範圍錯誤會顯示於個別圖層，其他圖層可繼續使用。
- 地圖預設中心與縮放在 `src/content/map.md` 維護。
